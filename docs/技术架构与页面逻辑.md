## 0. 一句话说清这个项目

**静态数据 + 全站 SSG + 零后端。**

100 条案例以 TypeScript 常量形式躺在 `src/data/cases.ts` 里，`next build` 时被编译进 HTML。运行时没有数据库、没有 API 请求、没有服务端逻辑。采集在 GitHub Actions 里由 Python 脚本完成，产出的结果通过 `git commit` 直接改写那个 TypeScript 文件——**用 Git 当 CMS**。

这个架构选择的代价和收益都很明确：

| | |
|---|---|
| **收益** | 零运维成本、零数据库费用、全站 CDN 可缓存、构建即校验（类型不对就构建失败）、内容变更有完整 Git 历史 |
| **代价** | 每次内容更新都要重新构建；投稿无法实时入库（走邮件人工处理）；数据量大到几千条时 bundle 会变大 |

### 1.4 构建与运行：/tmp 镜像机制

这是整个工程里最容易踩坑的地方，必须说清楚。

**问题**：云盘（`/Coze/Drive/`）的 IO 极慢，且 `node_modules` 放在云盘上会损坏（文件数太多、符号链接不兼容）。

**方案**：`scripts/local-workspace.cjs` 在每次 prepare / dev 时，把源码 rsync 到本地临时目录再操作。

```
云盘原件                          /tmp 镜像
/Coze/Drive/.../opc-graveyard/ →  os.tmpdir()/coze-web-{uid}/{sha256}/
                                   ↑ sha256 由源路径算出，同一项目固定同一镜像
```

**排除清单**：`node_modules` / `.git` / `.next` / `logs` / `tsconfig.json`

**防重入**：脚本靠环境变量 `COZE_WEB_LOCAL_ACTIVE` 判断当前是否已经在镜像里。三个脚本都是同一个模式：

```bash
if [[ "${COZE_WEB_LOCAL_ACTIVE:-}" != "${PROJECT_ROOT}" ]]; then
  # 还在云盘原件上 → 同步远端数据，然后跳进镜像
  bash "${SCRIPT_DIR}/sync-remote.sh" || true
  exec node "${SCRIPT_DIR}/local-workspace.cjs" prepare "$@"
fi
# 已经在镜像里 → 继续往下执行真正的构建
```

> ⚠️ **镜像里没有 `.git`。** 这意味着任何 git 操作都必须在 `exec` 之前、在云盘原件上完成。这也是 `sync-remote.sh` 被放在 `exec` 前面的原因——放后面就找不到仓库了。

### 1.5 三套脚本的分工

| 脚本 | 何时跑 | 做什么 |
|---|---|---|
| `prepare.sh` | dev 构建阶段 | 镜像 → `pnpm install` → 必要时初始化 |
| `dev.sh` | dev 运行阶段 | 镜像 → `pnpm next dev`，监听端口 |
| `validate.sh` | dev 校验阶段 | `pnpm validate`（ts-check + eslint + stylelint 并行） |
| `build.sh` | 生产构建 | `pnpm install` → `pnpm next build` → `pnpm tsup src/server.ts` |
| `start.sh` | 生产运行 | `node dist/server.js` |

`package.json` 的 scripts 全部是薄壳，实际逻辑都在 `./scripts/*.sh` 里：

```json
"dev": "bash ./scripts/dev.sh",
"build": "bash ./scripts/build.sh",
"start": "bash ./scripts/start.sh",
"validate": "pnpm dlx concurrently --group --names lint-tsc,lint-build,lint-style ..."
```

`src/server.ts` 只有 35 行——一个最小的 http 包装，让 Next 的构建产物能被外部进程拉起。生产/开发由 `COZE_PROJECT_ENV !== 'PROD'` 决定。

### 2.5 死因传导 `/chains`

这个页面的核心论点写在 h1 里：**「六个死因，不是六个格子，是五条路」**。

```typescript
const chains = FAILURE_CHAINS.map((chain) => ({
  chain,
  cases: chain.caseSlugs.map(getCaseBySlug).filter(Boolean),
}));

// 覆盖率：有多少条案例被至少一条链覆盖
const covered = new Set(FAILURE_CHAINS.flatMap((c) => c.caseSlugs));
const total = CASES.length;
```

五条链，每条结构为 `{ id, name, subtitle, steps[], logic[], caseSlugs[] }`，`steps` 里的每一步都带 `stage`（起点 / 加速 / 终局）和对应的死因 `tags`：

| id | 名称 | 一句话 |
|---|---|---|
| `self-hype-spiral` | 自嗨螺旋 | 从自己的痛点出发，做完了才发现只有自己需要 |
| `commodity-squeeze` | 平权绞杀 | 你的护城河是「比它更好」，而「更好」的保质期只有几个月 |
| `single-thread-life` | 命脉外包 | 全部流量/收入压在一个不属于自己的渠道上 |
| `single-decider` | 一个人拍板 | 没有第二个人能否决，错误决策一路走到底 |
| `fixed-cost-trap` | 重资产陷阱 | 固定成本先于收入发生，且不可逆 |

页面尾部有「全库主标签分布」，把标签计数与链路并置，让读者看到「分类」和「过程」的差别。

### 2.8 数据口径 `/data`

这是全站可信度的锚点。它在做一件很少见的事：**主动暴露自己的数据缺陷**。

```typescript
function quantile(sorted: number[], p: number) { /* 线性插值分位数 */ }

const lifes  = CASES.map((c) => c.lifespanMonths).sort((a, b) => a - b);
const median = quantile(lifes, 0.5);
const p25    = quantile(lifes, 0.25);
const p75    = quantile(lifes, 0.75);
const avg    = Math.round((lifes.reduce((s, x) => s + x, 0) / total) * 10) / 10;
```

六个区块：

1. **样本概况** — 总数、已验证数、中位数 / 四分位 / 均值
2. **死因分布** — 主标签计数 + 百分比，并明确写「在这个量级上，两个死因之间相差 2–3 条不足以说明谁更常见」
3. **存活时长分布** — 分桶（≤12 / 13–24 / 25–36 / …）
4. **已知的数据问题** — 字段缺失、口径不一致、来源不可核
5. **这个库不能用来推断什么** — 明确划出推论边界
6. 所有数字旁边都标 `n`

**这是「所有数字都带 n、所有结论都带边界」原则的实现位置。**

### 2.9 投稿 `/contribute`

**没有后端。** 表单提交时拼接 `mailto:`：

```typescript
window.location.href = `mailto:hello@opcgraveyard.com?subject=${encodeURIComponent(subject)}&body=${encodeURIComponent(body)}`;
```

`subscribe-form.tsx` 用同一套机制。

好处：零运维、零垃圾数据入库风险、不需要审核队列。
代价：依赖用户本地配了邮件客户端；没有提交回执；无法统计转化。

页面顶部有四个承诺标签：🚫 不评判不嘲笑 / 🔒 支持匿名 / ✅ 发布前与你确认 / 💡 你的教训将帮助上千名准 OPC 创业者。

### 2.10 关于 `/about`

静态叙事页，唯一的动态数据是 `CASES.length`（用于说明当前样本量）。内容覆盖：我们相信什么、方法论、内容来源、免责声明。

### 4.3 四源采集

| 源 | 实现 | 定位 |
|---|---|---|
| **GNews** | Google News RSS 关键词检索 | 主力：有报道的、有名有姓的失败 |
| **HN** | Algolia API `tags=story`，按 points/评论数过滤 | 补充：海外独立开发者项目 |
| **Stale** | 自研，见 4.5 | **主动发现**：没人报道、悄悄消失的项目 |
| **CN** | 中文媒体源 | 本土案例 |

四个池子按 **round-robin 交错合并**，而不是顺序拼接：

```python
order = ["gnews", "hn", "stale", "cn"]
idx = {k: 0 for k in order}
while any(idx[k] < len(pools[k]) for k in order):
    for k in order:
        if idx[k] < len(pools[k]):
            cands.append(pools[k][idx[k]])
            idx[k] += 1
```

**为什么这么做**：如果顺序拼接，`fetch_all(n=50)` 会先把 GNews 的 50 条全抓完，后面的源永远轮不上。交错之后，每个源都能进前 50，来源多样性有保证。

### 4.4 抓取与 LLM 抽取

**`fetch_all(cands, n=20)`** 有一层「免抓」优化：

```python
min_body = 120 if it.get("is_selfpost") else 60
```

正文本来就够长的（比如 HN 的 self post、RSS 全文），直接拿来用，不占抓取名额。

**`extract_cases(fetched, max_n)`** 把 `url + content` 塞进 `EXTRACT_PROMPT`，让 LLM 输出符合 `CaseRecord` 结构的 JSON。

**顺序很关键**：先调 LLM，后查重。原因是 LLM 抽取时可能判定「这不是一个商业失败案例」而返回空 slug——这类候选应该被丢掉，不应该占用去重名额。

### 4.5 沉默死亡追踪（`stale_tracker.py`）

这是本轮新增的第四通道，解决的问题是：**有大量项目死了但没有任何人报道**。它们只是某天域名到期没续，官网变成 404，然后就消失了。

**双闸门设计**——必须同时满足：

| 闸门 | 条件 | 判定方式 |
|---|---|---|
| 闸门一：时间 | ≥ 12 个月没有可观测活动 | HN Show HN 发帖时间距今 ≥ 12 个月 |
| 闸门二：存在性 | 站点确实消失了 | DNS `NXDOMAIN`，或根路径持续 404/410 |

**三条质量闸（防假阳性）**

这三条是踩了坑之后加的，每一条都对应一次真实的误判：

1. **一律用根路径重测。** 原 URL 可能是子路径（`nanonets.com/some-product`），子页面没了但公司活着。实测 Nanonets 是家融资数千万的真实公司，根路径 HTTP 200。所以 `_is_dead` 只用 `https://{root}/` 和 `https://www.{root}/` 测。
2. **子域死不算死。** `demo.duckui.com` NXDOMAIN，但 `duckui.com` 活得好好的。先取根域再判。
3. **5xx 一律不判死。** `goaliemvmt.com` 返回 530（Cloudflare 源站错误），可能是临时故障。宁可漏，不可错。

**商业性闸门。** 域名死了不等于这是个生意。第一版跑出过「地图记忆小游戏」和「Pitbull 歌词站」——域名确实死了，但它们从来不是商业项目。所以加了 `BIZ_SIGNALS`：讨论里必须出现 ≥ 2 个不同的商业信号（pricing / subscription / revenue / customers / MRR / churn / competitors …），否则判为「玩具不是生意」，跳过。

**分页策略。** Algolia 有个坑：`hitsPerPage * page ≤ 1000`。36 个月窗口有 18645 条 Show HN，翻页翻不完。改成**按月切片**，每次随机扫 2 个月份，36 个月 18 天轮完一轮。

**证据包。** 每个候选会生成一份人类可读的「沉默死亡检测报告」，包含 HN 帖子原文、按深度排序的评论、域名检测结果。后面跟一段强写作约束：

```
1. 融资额、收入、用户数、团队规模、创始人背景：材料里没有的，
   一律写「未披露」或空字符串，绝对不得推测或编造具体数字。
2. 死因拆解只能基于两件事：HN 评论里暴露的产品/运营/需求问题，
   以及「域名到期未续、产品无公告消失」这一事实本身。
3. closedAt 用「约 YYYY 年」，不要编造月份。
4. 如果 HN 评论少于 3 条有效内容…说明证据不足——slug 直接返回空字符串。
5. 如果这不是一个商业产品（纯开源工具、游戏 demo、个人博客、教程站），
   slug 直接返回空字符串。
```

**实测产出**（每轮约 148 秒）：`indiebackers.dev` / `quicklang.app` / `ext.store` / `logomvp.com` / `indiepulse.co` / `subout.tech` 等。

**台账。** `scripts/stale_seen.json` 记录已产出过的域名，避免每天重扫同一月份时把同一批候选反复喂给 LLM。

**已废弃的通道**

| 通道 | 状态 | 原因 |
|---|---|---|
| Indie Hackers | ❌ 不可用 | 三个子 sitemap 合计 105829 个 URL，`/product/` 路径数 = **0**（全是 post 和 ideas）；`/products`、`/api/products` 均被 Cloudflare 403 |
| GitHub 停更仓库 | ⏸ 备用 | 代码已就绪（`gh_stale_repos`），默认关闭，需要 `GITHUB_TOKEN` |
| Wayback Machine | ❌ 不可达 | 本环境对 `archive.org` 完全超时，无法用快照做二次证据 |

## 五、数据同步

### 5.1 问题

采集跑在 GitHub Actions（云端），它每天 push 一个 commit。但**本地云盘工作区不会自动 pull**。

结果：仓库里有 100 条，本地 demo 还停在 94 条。用户打开预览看到的永远是旧数据。

本次交付前的实际状态就是如此——`git fetch` 显示远端领先 1 个 commit（`b5e2fad chore: daily case harvest 2026-11-12`），案例数 94 vs 100。

### 5.2 机制化修复：`scripts/sync-remote.sh`

```bash
#!/bin/bash
set -uo pipefail

# 1) 没有 .git（跑在 /tmp 镜像里）直接退出
[ -d .git ] || exit 0

BEFORE=$(count_cases)                       # grep -c '^    slug: "' src/data/cases.ts

# 2) fetch，45 秒上限，失败就跳过（网络不好不能阻塞构建）
timeout 45 git fetch origin main --quiet 2>/dev/null || exit 0

# 3) 已是最新 / 本地领先 → 直接返回
# 4) 工作区有未提交改动 → 跳过，不把用户改动卷进合并
# 5) git merge --ff-only origin/main   只快进，永不产生冲突
# 6) 报告：BEFORE → AFTER 条案例
```

设计原则：**只做快进合并，任何一步失败都静默跳过，绝不阻塞构建。**

挂载位置在 `prepare.sh` 和 `dev.sh` 里，`exec` 到 /tmp 镜像**之前**：

```bash
if [[ "${COZE_WEB_LOCAL_ACTIVE:-}" != "${PROJECT_ROOT}" ]]; then
  # 必须在云盘原件上同步——/tmp 镜像里没有 .git
  bash "${SCRIPT_DIR}/sync-remote.sh" || true
  exec node "${SCRIPT_DIR}/local-workspace.cjs" prepare "$@"
fi
```

这样每次启动 dev / 构建预览，都会先把远端每日采集的案例拉下来，再镜像、再构建。

## 六、已知边界与缺陷

诚实列出来，避免后来者踩坑。

| 问题 | 现状 | 影响 |
|---|---|---|
| **无后端** | 0 个 API 路由，投稿/订阅全靠 `mailto:` | 无法统计转化、无提交回执、依赖用户本地邮件客户端 |
| **未部署** | `opcgraveyard.com` DNS 解析失败；500 条门槛未达（当前 100） | 只有本地/预览域可访问 |
| **`industry` 未归一化** | 「AI 远程医疗」「AI医疗」等近义值并存 | 筛选器里会出现重复选项，facet 计数被切碎 |
| **`closedYear` 格式不统一** | 有的是「2026」，有的是「约 2026 年」 | `localeCompare` 排序在边界情况下不严格 |
| **`secondaryTags` 有空值** | 部分案例为空数组 | 详情页徽章区可能只剩主标签 |
| **`verified` 仅 78%** | 78/100 已核实 | `/data` 页必须持续披露这个比例 |
| **弱引用静默失败** | 三个辅助数据文件用 slug 字符串引用案例 | slug 写错不会报错，只是那条不显示 |
| **镜像与原件分离** | `/tmp` 镜像排除 `.git` | 任何 git 操作必须在 `exec` 之前完成 |
| **Algolia 分页上限** | `hitsPerPage * page ≤ 1000` | 只能按月切片，36 个月 18 天轮完一轮 |
| **Wayback 不可达** | `archive.org` 在本环境超时 | 沉默死亡的证据链只有「HN 帖子 + 域名失效」两条 |
| **bundle 随案例数增长** | 100 条 ≈ 4793 行 TS | 到 500 条时需评估是否拆分/懒加载 |
